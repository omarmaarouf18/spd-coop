## Decisions taken
- **State lives in the run:** `CoopRun.missions` (a `MissionState`, `Bundlable`, key `coop_missions`) is mutated in place, so it is saved with every `Dungeon.saveGame()` and comes back with `Coop.restoreFromBundle()`; no extra save hook. Old co-op saves without the key load an empty state.
- **Resume = replay through the same code:** replayed reliable events go through `MissionState.apply()` like live ones, and every transition is idempotent: ended mission ids (last 16, saved) drop a replayed `MISSION_START`/`MISSION_END` (no double penalty), `MISSION_UPDATE` for another mission is ignored, a repeated `MISSION_START` of the active mission keeps its paused/tasks state. `complete:false` (no replay) keeps the saved state until the server sends newer events.
- **Server clock:** each `WELCOME`/`PONG` gives a sample `serverTime − localReceive`, which is the true offset minus that message's one-way delay; the clock keeps the **max of the last 6 samples** (≈ 1 min of PONGs) = the least-delayed one. No RTT/2 correction: the granted hook carries no PING send time; the residual error is the smallest one-way delay seen. A `WELCOME` (detected by the session still being in `HANDSHAKE` when the hook runs) drops the old samples: it may be another server process. `CoopSession` calls the hook **before** handing on the `WELCOME`'s snapshot, so replayed deadlines convert with the new epoch's clock.
- **Countdown:** deadlines are kept in server ms. While running, an unpaused `MISSION_UPDATE.remainingMs` resets the deadline to `serverNow + remainingMs` (the server moves its deadline when it pauses); while paused, the remaining time is frozen at the server's value.
- **Pause sources:** forced turns and the countdown stop when the mission is `paused` **or** the link is down locally (our session not `RUNNING`, or the ally offline per `ALLY_STATUS` / room snapshot), before the server's `MISSION_UPDATE{paused}` can arrive. Downed windows have no pause message: the client moves their deadlines by the time it saw the link down (approximation, see follow-ups).
- **Forced turns (D-005):** `ForcedTurns`, pure logic with an injectable clock; `WAIT_MS = 5_000`. The count starts at `Hero.ready()` or when the clock (re)starts, whichever is later (a resume never forces a turn at once). A forced turn = `GameScene.cancel()` (drops a pending cell selection, e.g. aiming a wand) then `hero.rest(false)`, the same as the toolbar's wait button. Driven every frame by the mission HUD on the GL thread; the `Hero` hook only stamps a time (actor thread). Applies to both players.
- **Forced turns while a window is open: yes, the pause menu included** (deviation from the prompt's recommendation, which excepted the pause menu). Reason: with the exception, the prisoner could open the pause menu and freeze their own world, so no wave ever reaches them; real absences (disconnect, app in background) are already covered by the server's pause. It's one condition in `CoopMissions.tick()` if the owner prefers the exception (see open questions).
- **MISSION_END application:** queued in the state (saved), applied once by `CoopMissions.tick()` when the hero waits for input. `success` → `MissionReward.grant(end)` (no-op until MEC-01 installs one); `failed` → gold `−goldPct %` (rounded down) then `InterlevelScene.Mode.RETURN` to `regionStartDepth`, `returnBranch 0`, `returnPos -1` (= the floor's entrance), after `Level.beforeTransition()`, exactly like `ScrollOfPassage`; `revived`/`aborted` → a log line, no penalty. `Dungeon.depth` is never written (a test scans `coop/mission/**` and `MissionHud` for depth writes). Listeners hear `onMissionEnd` at receipt (stop waves/unlock doors at once); the reward/penalty waits for the hero.
- **Penalty during a boss fight:** while the current floor is a sealed boss floor (`level.locked && Dungeon.bossLevel()`), the whole failed END waits (vanilla blocks inter-floor teleports there too). Other floors, the mines included, are left at once. A dead hero gets no reward/penalty (the real death path owns them).
- **HUD:** `coop/ui/MissionHud`, centered under the boss bar on the UI camera, both players: line 1 = kind + `m:ss` (rounded up) or the pause reason (`paused (ally offline)` / `paused (reconnecting...)` / `paused`); line 2 = a checkbox icon + label per task flag (`task_key` → "Key"; a flag without a label shows its wire name); a Downed window adds `You are downed: m:ss` / `Ally (Mage) is downed: m:ss`. Hidden when no clock is active. `GameScene` adds it after the boss bar so it's drawn above the map; the hook is a no-op outside co-op runs.
- **allyConnected fix:** `CoopConnection.allyConnected()` now also follows the room snapshot (`ROOM_STATE` / the room in `WELCOME`: the ally's `connected`), and a **live** `RUN_START` sets it to true (the server only starts a run with both players connected, PROTOCOL.md §6). A snapshot `RUN_START` doesn't change it. `ALLY_STATUS` still has the last word.
- Super Sync and Downed: state only (`MissionState.sync()`, `downed()`, `isOut()`) + listener callbacks; behavior is MEC-02 / SYN-01.

## API for MEC-01 / MEC-02 / SYN-01 (all on the GL thread, `coop.mission.CoopMissions` unless noted)
- Listen: `CoopMissions.addListener(MissionListener)` / `removeListener(...)`. `MissionListener` (all default no-ops): `onMissionStart(Mission)`, `onMissionUpdate(Mission)`, `onMissionEnd(End)`, `onAllyDowned(String playerId, long deadline)`, `onRevive(String targetId, String mode, int hpPct)`, `onDownedExpired(String playerId)`, `onSyncStart(Sync)`, `onSyncEnd(String syncId, long hpLost, String reason)`. Called only for messages the mirror accepted (never twice for a replay).
- Reward: `CoopMissions.reward(MissionReward)`; `MissionReward.grant(MissionState.End end)` gets `end.rewardSeed` and `end.mission` (MEC-01 rolls the Cell's loot from the seed).
- Query: `state()` (the run's `MissionState`, null outside co-op), `mission()`, `missionActive()`, `isPrisoner()`, `isRescuer()`, `me()`, `missionRemainingMs()`, `isDowned(playerId)`, `downedRemainingMs(playerId)`, `syncActive()`, `clockRunning()`, `linkUp()`, `serverNow()`, `clock()` (`ServerClock.toLocal/serverNow`), `forcedTurns()` (`ForcedTurns.msUntilForced(...)`, `ForcedTurns.WAIT_MS`).
- `MissionState.Mission` fields: `id, kind, prisoner, rescuer, depth, branch, trapCell, roomId, keySeed, startsAt, deadline, waveIntervalMs, paused, tasks`; `remainingMs(serverNow)`. `MissionState.End`: `missionId, result, regionStartDepth, goldPct, rewardSeed, mission`, `failed()`, `success()`. `MissionState.Sync`: `id, snapshot, turns`.
- Penalty helpers (MEC-02's Recall "regionStart" revive can reuse the travel): `MissionPenalty.goldLost(gold, pct)`, `MissionPenalty.travelBlocked()`; the RETURN travel itself is `MissionPenalty.apply(end, switchScene)` (package-private `returnTo(depth, switchScene)` if MEC-02 wants it public, ask).
- Sending (unchanged, PRO-02): `CoopConnection.session().missionTrigger(...)`, `.give(... "cell_key" ...)`, `.downed(...)`, `.useRecall(...)`, `.syncDrink/syncView/syncCmd/syncReport(...)`.

## Follow-ups / out-of-lane findings
- **SRV-02:** resend `ALLY_DOWNED{deadline}` (new deadline) when a frozen Downed window resumes; the client's local shift is an approximation (it only counts while a `GameScene` is up).
- **SRV-02 / PROTOCOL:** `MISSION_UPDATE` replays carry an old `remainingMs`; a fresh `MISSION_UPDATE` right after a resume (the unpause one) fixes the countdown. Worth stating in PROTOCOL.md §5.6 that the server sends one on every resume.
- **Design conflict for MEC-02 (not decided here):** PROTOCOL.md §5.8 says an expired Downed prisoner plays the real death path and the server also sends `MISSION_END{failed, penalty}`, while game-design §4.3 says both players return to the region start. MEC-00 skips the penalty for a dead hero.
- The protocol only defines the task flag `key`; the decoder drops any other flag (unknown s2c fields, §5.5), so a new task flag needs a PROTOCOL change before the HUD can show it.
- `windows.properties` and `CoopConnection.SessionListener` are likely touched by ITM-01 too (`onServerEvent` will need item events): expect a small merge.
