## Problem
`setup_jdk` took field 2 of every line `javac -version` prints on stderr. When `JAVA_TOOL_OPTIONS` is set (Claude cloud containers set it for their HTTPS proxy), the JVM first prints `Picked up JAVA_TOOL_OPTIONS: ...`, the parsed version became `''`, and the gate blocked with `JDK at ... is version ''` even with a valid JDK 21.

## Decisions taken
- Parse only the line whose first field is `javac`, first match only (`awk '$1 == "javac" { print $2; exit }'`). Machines without `JAVA_TOOL_OPTIONS` see no change.

## Verification
- Cloud container, `JAVA_TOOL_OPTIONS` set: the old parse printed `up` and `21`, so the gate blocked with `JDK at /usr/lib/jvm/java-21-openjdk-amd64 is version ''`. The new parse prints `21`, and `make check` reached `JDK: ... (javac 21; CI uses 17)`, java `BUILD SUCCESSFUL`, server ok. Its docker stage is blocked by the cloud sandbox's TLS-intercepting proxy (unrelated to this change).
- Owner's machine (Fedora, javac 27): `make check` PASS, all stages (scope `java server docker protocol docs actions shell secrets`), `JDK: /usr/lib/jvm/java-latest-openjdk (javac 27; CI uses 17)`.
