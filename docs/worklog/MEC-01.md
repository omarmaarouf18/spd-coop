## Decisions taken
- **Placement (co-op gen, after `level.create()` and the co-op balance):** its own generator, `Random.pushGenerator( Dungeon.seedForDepth( depth, branch ) ^ SALT )`, so it never moves the level's RNG stream (golden diff below: only `map`/`traps` change). 50% per eligible floor (§4.7 "~1 per 2 floors"). Eligible floor: `RegularLevel`, branch 0, depth 2–24, not `Dungeon.bossLevel`. Eligible room: a `StandardRoom` whose class is directly in `levels.rooms.standard` (so not the `entrance`/`exit` sub-packages, not quest rooms like the mines or the Blacksmith), not `ImpShopRoom`, with at least one door. Special/secret rooms aren't StandardRooms. Cell: `Terrain.EMPTY` inside the room, no trap/heap/plant/mob/transition, not next to a door. Rooms in `level.rooms()` order and cells in ascending order, so both worlds pick the same one.
- **Quest branches excluded** (mines/vault floors): my reading of "special" rooms. Revisit if the owner wants Cells in the mines.
- **The trap carries its room:** rect, `roomId` = `1 + (depth×10+branch)×65536 + (top×width+left)` (content-defined, 1..2^53−1, per PROTOCOL §3), door cells from `Room.connected`. Saved under `coop_*` keys in the trap bundle.
- **Trigger:** `BindingTrap.trigger()` (disarmedByActivation off) → `CoopCell.onTriggered` → `MISSION_TRIGGER` posted to the GL thread, only if: co-op run, trap active, the hero stands on it, no mission in the mirror, ally online on the same floor (same check as LINK-01/ITM-01). A found (visible) trap is pressed by mobs/items too: those are ignored. No local "pending" state: a `DENY` changes nothing and the next step asks again (the server answers `mission_active` for a duplicate). `MISSION_START` spends it (reveal + `disarm()`) in both worlds.
- **Listening without a co-op start hook:** `CoopCell`'s static init registers its `MissionListener` and `MissionReward`; every class that can be part of a Cell loads it (`placeTrap` on every co-op floor, `BindingTrap`, `CellPrison`, `CellRescue`, `CellKey` static blocks). A client can only get a `MISSION_START` on a floor with a Binding Trap loaded, and a resumed rescuer/prisoner has the buff on the hero. The two upstream hooks also load the class in vanilla; that only adds a listener that is never called and sets the (unused) reward, no gameplay change. A one-line `CoopCell.install()` in a co-op start path would be cleaner (Coop.java was out of lane).
- **Prisoner (`CellPrison`, a hero buff, saved with the hero):** seal = `Level.set( door, LOCKED_DOOR )` in this world only (LINK-01 never sees `Level.set`); the original tile is kept and put back on unseal (an open door comes back closed). A door that is already locked (e.g. the door to a neighboring vault) is left alone and stays locked. A door with a char in it or an unfound secret door is sealed as soon as possible (every turn the buff retries); a door unlocked with a spare iron key locks again (the key is spent: accepted edge case). If the prisoner stepped out before `MISSION_START` arrived, they're put back on the trap cell (`ScrollOfTeleportation.appear`).
- **Waves:** `CellWaves`, pure logic on the mission clock: `elapsed = cap − remaining` (remaining frozen while paused; the server moves its deadline), cap = `deadline − startsAt` **taken once at MISSION_START** (found by the pause test: the moved deadline would stretch the cap). Wave 0 at once, wave k at k×`waveIntervalMs`; tier = wave/2; `1 + tier` mobs (max 6) from `MobSpawner.getMobRotation( min( depth + tier, regionLast ) )` (regionLast = 4/9/14/19/24). After the cap (overtime, no server END yet): lethal, twice as often, +2 mobs, next region's last floor. At most one wave per buff act; none while `CoopMissions.clockRunning()` is false or the prisoner is Downed. Spawned with this world's gameplay RNG (prisoner-only content), inside the cell ≥2 tiles from the prisoner, or 2–3 tiles around them if they escaped. Wave mobs already in stay after the end.
- **Rescuer (`CellRescue`, hero buff):** spawns the Cell Key once when the rescuer is on the mission floor (at once, or on coming back), at `CellLayout.keyCell`: candidate `floorMod( keySeed, n )` of the ascending list of terrain cells that are walkable (not secret), not avoid/pit/door/stairs, reachable from the entrance (`PathFinder` over the terrain flags: locked/secret doors block), ≥3 tiles from the cell's rect. Computed from terrain only, so the same keySeed gives the same cell every time (heaps/chars/hero position don't matter). Local ping (`Marks.Kind.ITEM`, local only). `CoopItems.markLocal( key )`. No candidates: straight into the backpack.
- **Key / GIVE:** `CellKey` (iron-key sprite, USE default). USE next to or in a door of the cell (from the trap's door list in the rescuer's world) → `GIVE{cell_key}` with itemNetId `<rescuer>:<1e9 + keySeed mod 8999999999>` (valid per PROTOCOL §3, above CoopItems' runtime counters). Too far: hint, nothing sent; not connected: hint. The key goes on `MISSION_UPDATE{tasks.key:true}` or any END; a key of an ended mission crumbles when picked up.
- **End:** any result → `CellPrison.finish()` (unseal now, or when back on the floor) and `CellRescue.finish()` (keys in hand and on this floor removed). Penalty: MEC-00. Downed prisoner: MEC-02. Safety net: a prison buff whose mission is gone from the mirror unseals on its next act.
- **Reward (`CellReward`, installed with `CoopMissions.reward`):** its own generator seeded with `rewardSeed * φ ^ FNV-1a64(playerId)`; draws kind (artifact / +2 / exotic, a third each) and **always** all three candidates (same RNG use whatever the kind): uniform artifact class (uncursed), +2 weapon/armor/wand/ring from default probabilities (`randomWeapon(floorSet,true)`, `randomArmor`, `randomUsingDefaults`, no decks touched), uncursed and curse-enchant/glyph removed, floor set = mission depth/5; exotic from `regToExo` (LinkedHashMaps). Only world-dependent step: `Generator.removeArtifact`; if that artifact was already generated in this world, the +2 item instead (artifact uniqueness). Item marked LOCAL, collected (or dropped on the hero), plus `Bonded` (FlavourBuff, 200 turns, BLESS icon tinted violet, ×1.1 accuracy).
- Strings: appended to `windows.properties` (where MEC-00 put its co-op strings).
