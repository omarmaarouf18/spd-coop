## Problems fixed
1. **Gradle crashed on JDK 27 EA** (`Unsupported class file major version 71`) whenever a `build.gradle` changed: the owner's default JDK is 27 EA, Gradle 9.5 runs on Java ≤ 26. Every gate run and `make push` needed `JAVA_HOME=$HOME/jdk17` by hand.
2. **The Docker end-to-end check took 8 commands** (compose up, probe `-state`, restart, probe `-resume`, down) and a missing `GOTOOLCHAIN` broke it (`go: go.mod requires go >= 1.27.2 (running go 1.26.9; GOTOOLCHAIN=local)`).

## Decisions taken
- `tools/versions.env` gains `GRADLE_MAX_JDK=26` (docs.gradle.org compatibility table: running Gradle on Java 26 since 9.4.0; 27 is not listed).
- `setup_jdk` keeps JAVA_HOME / the `javac` on PATH when it is within `JDK_VERSION..GRADLE_MAX_JDK`. Otherwise it scans `/usr/lib/jvm/*`, `~/jdk*`, `~/.jdks/*`, `~/.sdkman/candidates/java/*` and uses the **newest** JDK in range, printing which one and why; with none it blocks with an install hint. The gate exports the chosen `JAVA_HOME`, so `make check`, `make push` and the pre-push hook all use it.
- `make server-probe` → `scripts/server-probe.sh`: `compose up -d --build --wait` (the dev compose healthcheck), `lobbyprobe -state`, `restart server` + `up -d --wait`, `lobbyprobe -resume`, and `compose down` in an EXIT trap (also on failure; the data volume is kept). Go runs with `GOTOOLCHAIN=go$GO_VERSION` from `tools/versions.env`. The state file (two test resume tokens) lives in a mode-700 temp dir and is deleted.
- `server/README.md` documents `make server-probe` and the `GOTOOLCHAIN` fix for manual `go run`.
- Not changed: CI (it pins JDK 17 already) and the cloud-only docker limitation (not worth a repo change).
